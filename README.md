# Fighting — 2D браузерный файтинг (Vue 3 + TypeScript)

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # vue-tsc + vite build → dist/
npm test           # юнит-тесты боевой системы, AI-матчей и storage
```

## Управление по умолчанию

| Действие | Игрок 1 (клавиатура) | Игрок 2 (клавиатура) | Геймпад (Xbox) |
|---|---|---|---|
| Влево / вправо | A / D | ← / → | D-pad, левый стик |
| Прыжок | W | ↑ | A (и D-pad ↑) |
| Слабый удар | J | Num1 или `,` | X |
| Сильный удар | K | Num2 или `.` | Y |
| Удар ногой | L | Num3 или `/` | B |
| Спецприём | U | Num5 или `'` | RB |
| Блок (удерживать) | I | Num0 или RShift | LB |
| Пауза | Esc | Backspace | Start |

Всё переназначается на экране «Управление», выбор устройств и привязки хранятся в localStorage.
Игрок без подключённого устройства на экране выбора персонажа может «подключиться», нажав любую кнопку
свободного геймпада или свою клавишу удара.

## Ассеты

Исходники не изменяются:

- `figther-1/`, `figther-2/` — спрайт-листы персонажей (17k×32k px, непрозрачный фон `#232323`);
- `scene/` — фон арены (подхватывается автоматически, первый файл по имени);
- `materials/` — макеты экранов (только как референс стиля).

Браузер не может загрузить листы такого размера, поэтому `tools/slice_sprites.py` один раз
нарезает их в `public/assets/fighters/<id>/` (`atlas.webp` + `atlas.json` + портреты):
вырезает кадры, убирает фон, уменьшает до 25 % и вычисляет точку опоры кадра (по голове персонажа).

```bash
npm run slice                                          # пересобрать всех
python tools/slice_sprites.py <id> "<папка>/<лист>.png" --preview   # один новый боец
```

Нужен Python 3 с Pillow, numpy и scipy.

## Как добавить бойца

1. Положить лист в `figther-3/` (та же раскладка: строка 0 — портреты, далее ряды анимаций).
2. `python tools/slice_sprites.py rookie "figther-3/Новичок.png" --preview` — проверить превью рядов.
3. Создать `src/game/fighters/defs/rookie.ts`, экспортировать `FighterDefinition` по умолчанию
   (за основу взять `developer.ts`): ряды/кадры анимаций, атаки с frame data, хитбоксы, комбо, спецприём.

Реестр подхватывает файл автоматически; боевая система, AI и UI не меняются.
При загрузке боя `validateFighter` проверяет, что все упомянутые кадры есть в атласе.

## Звук и музыка

Файлы кладутся в папку `audio/` в корне проекта (форматы: ogg, mp3, wav, m4a, webm) и подхватываются
автоматически после перезапуска `npm run dev` / пересборки.

| Файл | Где звучит | Как играет |
|---|---|---|
| `audio/music-menu.*` | меню, выбор персонажа, управление, настройки, результат | бесшовный луп |
| `audio/music-vs.*` | экран VS перед боем | один раз; экран держится до конца трека, финальный удар совпадает с переходом в бой (Enter / A — пропуск) |
| `audio/music-fight.*` | бой | бесшовный луп, кроссфейд из VS |

Лупы играются через WebAudio: тишина, которую MP3-кодеры добавляют в начало и конец, обрезается
автоматически. Для идеального стыка лучше всего OGG или WAV.

Звуковые эффекты — файлы с именами из `src/game/audio/sounds.ts` (`hit-light.mp3`, `ko.ogg`, …).
Пока их нет, звучат короткие синтезированные эффекты (отключаются в настройках).

## Архитектура

```
src/game/
  core/      fixed-timestep loop (60 Гц), конфиг боя, пул событий, базовые типы
  input/     InputManager (клавиатура + Gamepad API), привязки, InputSource
  combat/    Fighter (state machine), FighterController, CombatSystem, комбо, выбор кадра
  fighters/  типы FighterDefinition, реестр, defs/ — данные бойцов
  ai/        AiController — тоже InputSource, видит противника с задержкой реакции
  rounds/    Match: READY → FIGHT → KO/TIME → best of 3
  vfx/       частицы, вспышки, тряска экрана (без аллокаций в цикле)
  audio/     AudioManager (файлы или синтез)
  render/    Canvas 2D рендерер
  bridge/    HudBridge — снимок для HUD без Vue-реактивности на 60 Гц
  storage/   версионированный typed localStorage (controls, settings, statistics)
  fight-session.ts — связывает всё в один бой
src/ui/      Vue-экраны: меню, выбор персонажа, бой + HUD, результат, управление, настройки
```

Поток ввода: `устройство / AI → InputFrame → applyInput (state machine) → CombatSystem`.
Боевая система не знает, кто нажал кнопку — игрок, геймпад или AI.

Настраиваемые значения: `src/game/core/config.ts` (блок, энергия, комбо-окна, раунды, физика)
и файлы бойцов (урон, frame data, хитбоксы, нокбэк, стоимость спецприёма).
